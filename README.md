## 🛠️ Установка и локальный запуск

Требуется Node.js 22.18.0 (версия зафиксирована в `mise.toml`).

```bash
git clone https://github.com/maximusw124/ai-for-developers-project-387.git
cd ai-for-developers-project-387
npm ci
npm run dev
```

После запуска бэкенд доступен на `http://localhost:3000`, фронтенд — на `http://localhost:5173`.

Если используется mise:

```bash
mise run install
mise run dev
```

## Проверки

```bash
npm run check   # контракт, линтер, типы, сборка и тесты (эквивалент mise run check)
npm run e2e     # сквозные Playwright-тесты (эквивалент mise run e2e)
```

### Политика карантина нестабильных тестов

- Упавший в PR тест не перезапускается ради зелёного статуса; ретраи в PR запрещены.
- Если нестабильность подтверждена (падение в nightly без изменения кода или проход только со второй попытки), открывается тикет, а тест помечается `test.fixme(...)` с номером тикета — это карантин.
- В карантине тест остаётся видимым, но не блокирует PR. Возвращение в обычный прогон происходит той же правкой, которая закрывает тикет.
- Маскировать нестабильность ретраями, отключением трассировки или безосновательным увеличением таймаутов запрещено.

## 🤖 Автоматизация через OpenCode GitHub App

В репозитории подключён [OpenCode GitHub App](https://github.com/apps/opencode-agent) и воркфлоу `.github/workflows/opencode.yml`. Он позволяет вызывать агента прямо из обсуждения тикета или пулл-реквеста.

- **Событие запуска:** только `issue_comment` типа `created`, то есть новый комментарий к Issue или PR. Другие события агента не запускают.
- **Команды вызова (mentions):** `/oc` и `/opencode`, например `/oc объясни этот тикет`. Команда распознаётся как отдельное слово: `/octocat` или `/ocnr` не срабатывают.
- **Допуск:** комментарий должен быть от OWNER, MEMBER или COLLABORATOR и не от бота. PR из fork не получают доступ к секретам: такой вызов отсекается до запуска агента.
- **Модель:** `opencode/big-pickle`. Ключ читается из секрета репозитория `OPENCODE_API_KEY` (Settings → Secrets and variables → Actions).
- **Назначение воркфлоу:** быстро разобраться в тикете, предложить правку или подготовить PR, сохраняя человека ответственным за финальное решение. Один запуск на номер Issue/PR, таймаут 15 минут, предыдущий запуск не отменяется.
- **Где смотреть результаты:** ответ агента появляется комментарием в Issue/PR; журнал, команды и ошибки — во вкладке Actions в запуске `opencode`.
- **Решение по `share`:** `false`. Репозиторий открытый, поэтому сессии намеренно не публикуются внешними ссылками; результаты остаются только в комментариях и логах Actions.

### Автотриаж новых обращений

Отдельный воркфлоу `.github/workflows/auto-triage.yml` запускается на событие `issues` типа `opened` и делает предварительный разбор через скилл `triage`.

- **Допуск:** триаж запускается только для Issue от OWNER, MEMBER или COLLABORATOR и не от ботов.
- **Пропуск подготовленных тикетов:** Issue с меткой `ready-for-agent`, любым другим служебным state-лейблом (`needs-triage`, `needs-info`, `ready-for-human`, `wontfix`) или меткой `wayfinder:*` не разбирается повторно. Так тикеты, уже подготовленные скиллами `to-spec`/`to-tickets`, не попадают в автотриаж.
- **Параллельность:** `concurrency` группируется по номеру Issue (`auto-triage-${{ github.event.issue.number }}`), `cancel-in-progress: false` — уже идущий разбор не отменяется.
- **Таймаут:** 15 минут на джобу.
- **Границы агента:** изучает код и документацию, оставляет комментарий с предварительным выводом и уточняющими вопросами, обновляет метки трекера; код не меняет, коммиты, ветки и PR не создаёт.

## 🚀 Пользовательский сценарий (User Journey)

Ниже описан базовый сквозной сценарий работы сервиса: от настройки типа встречи владельцем до записи гостя и появления события в системе.

### Этап 1. Настройка типа встречи (Владелец)

1. Владелец переходит в раздел создания событий (**Event Types**) и нажимает кнопку создания нового типа встречи.
2. Заполняет основные параметры:
   - **Название (Title):** например, *«Консультация»* или *«30 Min Meeting»*.
   - **URL-слаг (Slug):** уникальный адрес для ссылки.
   - **Длительность (Length):** например, *30 минут*.
   - **Место проведения (Location):** выбор платформы для звонка (видеосвязь или очная встреча).
3. Сохраняет настройки — после этого создается публичная ссылка вида `domain.com/username/event-slug`.

### Этап 2. Запись на свободное время (Гость)

1. Гость переходит по публичной ссылке владельца.
2. В интерактивном календаре выбирает нужную дату и доступный временной слот.
3. Заполняет форму бронирования (указывает имя, email и при необходимости комментарий).
4. Подтверждает бронирование — отображается экран успешной записи (*Confirmation Screen*).

### Этап 3. Фиксация бронирования (Владелец)

1. Владелец открывает панель управления и переходит в раздел бронирований (**Bookings** -> **Upcoming**).
2. В списке появляется новая карточка встречи с данными гостя, выбранным временем и ссылкой на звонок. Занятый слот автоматически блокируется в календаре.

## 🌐 Развёртывание (Render)

Образ собирается из корневого `Dockerfile`: multi-stage сборка контракта, генерация API-клиентов, сборка фронтенда и бэкенда. Финальный контейнер запускает `node backend/dist/index.js` и раздаёт SPA и API с одного порта. Render задаёт переменную `PORT` автоматически, приложение слушает `0.0.0.0`.

### Подключение Render MCP без секретов в репозитории

`opencode.json` описывает удалённый MCP-сервер Render:

```json
{
  "mcp": {
    "render": {
      "type": "remote",
      "url": "https://mcp.render.com/mcp",
      "headers": { "Authorization": "Bearer {env:RENDER_API_KEY}" }
    }
  }
}
```

В конфиге нет ключа, токена и данных сессии: opencode подставляет значение из переменной окружения `RENDER_API_KEY`.

Шаги входа:

1. В Render Dashboard откройте **Account Settings → API Keys** и создайте ключ с доступом только к нужному workspace.
2. Задайте переменную в Shell до запуска opencode:
   ```bash
   export RENDER_API_KEY='...'
   ```
   либо в PowerShell:
   ```powershell
   $env:RENDER_API_KEY = '...'
   ```
   Не добавляйте значение в `.env`, который попадает в git.
3. Перезапустите opencode: конфиг читается только при старте. Проверьте соединение вызовом `list_workspaces`, затем задайте рабочий workspace (например, `Set my Render workspace to <name>`).
4. В редакторах с поддержкой OAuth (Claude Code, Codex, Cursor, Claude Desktop) можно войти через браузер без API-ключа: официальный Render plugin/connector, URL `https://mcp.render.com/mcp`. Для opencode используется вариант с переменной окружения выше.

### Хранение данных

Приложение использует SQLite по пути `/data/booking.db` (переменная `DATABASE_PATH` в образе). Без подключённого постоянного диска `/data` находится в записываемом слое контейнера: при перезапуске или редеплое сервиса данные удаляются. Чтобы записи сохранялись, подключите Render Persistent Disk к `/data` (доступно на платных планах) и оставьте `DATABASE_PATH=/data/booking.db` без изменений.
